## 后续 KOP 更新方式

- 生产代码固定 KOP 精确提交，上游更新不会直接改变线上版本。
- `.github/workflows/sync-kop.yml` 每周检查上游并创建 PR，不自动合并。
- 也可手动执行 `npm run sync:kop`，随后运行 `npm run check`。
- 审查同步 PR 时遵循 `AGENTS.md` 与 `doc/PROJECT_STATUS.md`，不要直接修改 `vendor/kop-xiao/resource-parser.js`。
- 合并前至少真机复测：一个自有 YAML 节点资源、一个分流、一个重写。若新版不兼容，不合并 PR 即可，当前线上版本不受影响。
